# Darkroom numerical core

Pinned source: https://github.com/darktable-org/darktable/tree/release-5.2.1 . Sources are included unchanged under `upstream/` (src/common/curve_tools.{c,h}, src/develop/imageop_math.h, src/gui/draw.h, src/iop/{basicadj,rgbcurve}.c). Original copyright notices apply. The extracted and adapted darktable C kernel and its build sources are distributed under GPL-3.0-or-later; see COPYING. The detector, neural model and third-party runtimes are not upstream darktable material.

Local adaptation (2026-11-21): the host sends packed float linear-sRGB triples instead of darktable RGBA. No auto settings, profile selection or black-level offset. The exposure scale, highlight shoulder (threshold parameter zero), brightness and saturation/vibrance follow basicadj; contrast uses its luminance-preserving branch with sRGB D65 weights and pivot 0.1842. The curve sampler is the actual monotone-Hermite CurveDataSample implementation. Tables use 65536 samples and draw.h normalization by 65536. From input 1 upwards, rgbcurve's four-point power fit continues the response. The master curve uses a luminance ratio; optional R/G/B curves follow the master. Negative outputs are floored only at the model-input boundary. A neutral host configuration bypasses the kernel. These host choices are not a claim of full pixelpipe equivalence.

The host's input boundary in darkroom.py clamps to [0,64] and maps NaN to zero; upstream unbounded curve math itself has not been altered for positive inputs. This is relevant when multiple extreme HDR channel extrapolations compound.

V1.0.1 extends only the upper half of the highlight slider. After the standard basicadj shoulder, for compressed luminance L > 0.30 and slider s > 0.50, the second shoulder maps L to 0.30 + log1p(k × (L − 0.30)) / k, with k = 18 × (2s − 1)². Hue is preserved by a common RGB gain; the derivative is one at the knee. The extension is JTL tuning, not an upstream darktable default.

To rebuild, use CPython 3 then `python prepare.py` in this directory; this extracts the original functions and saturation block directly. With LLVM clang and the native SDK available: Windows x64: `clang -O2 -ffp-contract=off -shared kernel.c -o ../jtl-darkroom-win.dll`. On a Mac: `clang -O2 -ffp-contract=off -dynamiclib kernel.c -o ../jtl-darkroom-$(uname -m).dylib`. Cross-build with LLVM by compiling `kernel.c` with `-target ARCH-apple-macos13.3 -DJTL_CROSS -ffreestanding -O2 -ffp-contract=off -c` and linking with `ld64.lld -arch ARCH -dylib -platform_version macos 13.3 13.3 -install_name @rpath/jtl-darkroom-ARCH.dylib -adhoc_codesign -o ../jtl-darkroom-ARCH.dylib kernel.o system.tbd` (ARCH is arm64 or x86_64). No network or machine-specific SDK is required to run the resulting app.
