- 接受 JPEG、PNG、TIFF，以及 LibRaw 能解码的相机 RAW（包括部分 DNG、CR2/CR3、NEF、RAF、ARW 等；并非每一型号或压缩格式都支持）。RAW 用相机白平衡和线性 sRGB 解码；普通照片转换到 sRGB，应用方向信息。

## 影调和颜色

Bayer RAW 沿用原 JTL 的 RawTherapee 5.12 颜色传播（HLRecovery_inpaint，blur=0）：在完整、已白平衡的相机 RGB 上，按有效裁幅及方向恢复高光，再缩图、转换色彩矩阵和调色。不会强制把彩灯变白，也不能找回所有通道都已剪切的真实颜色或细节。JPEG 和已显影的 RGB 不走这一步。问题反馈： QQ 1025168246。

「曝光」以档为单位（±3 EV），在线性输入上倍增或减半；「亮度」改变幂曲线，并不等同于曝光。「对比度」以 18.42% 中灰为支点、按亮度保持 RGB 比例。「高光压缩」沿用 darktable 的肩部公式，不是 RAW 高光重建。

高光压缩的 0–50% 保留原响应，后半程逐渐加重：完成原压缩后，仅对线性亮度高于 30% 的部分再压一段。100% 时，线性白点输入在进调色模型前从旧版的约 69% 降到约 42%；更亮的层次仍依次递增，不是把它们剪成同一种灰。

「颜色」分饱和度和自然饱和度。想只压暗部里的红色而保留其他通道，进入「曲线 → 红通道 → 阴影」，下拉节点或精确输入输出百分比。总明度曲线保持颜色比例，三个颜色通道则独立。「调阴影」「调高光」直达总明度曲线的相应节点。黑白端点固定、中间五个节点可调，节点不可交叉；显示轴扩展暗部以便操作，数字始终是线性输入、输出值。

计算顺序：曝光 → 高光压缩 → 亮度 → 对比度 → 饱和度/自然饱和度 → 总明度曲线 → 独立 RGB 曲线 → 调色模型。零设置直接旁路，保留原有成像。采用 darktable release-5.2.1 的基本调整和 RGB 曲线核心；我们固定线性 sRGB 工作空间和节点范围，未复制 darktable 的整个 RAW、色彩管理和显示管线。对应代码、改动和构建方法均随包保留在 `assets/darkroom-src`。

曲线对白点以上的输入使用 darktable 的幂函数外推，不在 1.0 剪白。极端多通道曲线叠加可能溢出；JTL 在送进网络之前做最后一个保护，把输入限制在线性 0–64（名义白点以上 6 档），非数值按零处理。这是模型边界，不是 darktable 的曲线定义。

## 全图加速

「处理全图」仍逐原始像素显影，不用放大的预览代替成片。Windows 自动尝试使用 DirectML 处理 BayerNet 和两套徕卡模型，在显卡上计算原网络的三线性查表和空间控制图。Apple 芯片尝试用 Core ML 运行 BayerNet，并在首块与 CPU 对照；其他 Mac 可使用 CPU。各平台都尝试用 OpenCL 执行原参数的 16 位色差降噪。没有合适的设备或驱动、设备计算失败时，自动回到 CPU，不影响导出尺寸和格式。无需安装 CUDA。排查驱动问题时可设置环境变量 `JTL_CPU_ONLY=1` 以全程使用 CPU。

## RAW 和质感

本版直接加载由 LibRaw 官方 `master` 提交 `40fb564486681a04eba0318058b0519f4f69eba8` 构建的解码库，运行时版本为 **0.23.0-Snapshot202611**。这是截至 2026-11-21 核对的开发快照，不是稳定发行版。不会调用系统 LibRaw 或 rawpy 的旧库。随包提供源码、构建入口与许可；启用 zlib 和 IJG JPEG，未集成可选商业 DNG SDK、RawSpeed 或已弃用的 RED 解码器。

- 标准方形像素的 2×2 RGB Bayer RAW 使用原 JTL 的 BayerNet（Gharbi 等人的 BayerDemosaick，原权重 SHA-256：`a90f45c34b89fea3faf49060687839a7d191d302f597a302b31d1bbc021ff7d8`）。LibRaw 解包后按可见区 CFA 相位、各通道黑白电平和相机白平衡准备输入，转换到网络使用的 1/2.2 域。全图分块保留覆盖网络感受野的 36 像素上下文，再转换到线性 sRGB。不对已是 RGB 的照片二次解拜尔。非标准 Bayer、X-Trans 或特殊像素几何由 LibRaw 兼容解码，不冒称 BayerNet。
- 「质感 → 降彩噪」只平滑色差：在 sRGB 编码空间保留 Rec.709 加权亮度，对两路 16 位色差联合使用 OpenCV 非局部均值（L1 距离，3×3 对比块、9×9 搜索窗），然后限制在可显示色域。默认 30%，设成 0 可旁路。这不是 darktable 的 profiled denoise。
- 「M9 颗粒」沿用原 JTL 配方：关闭、轻柔（0.55×）、标准（1×，默认）、浓郁（1.4×）。可跟随原片拍摄 ISO（读不到使用 400）或选 14 个 ISO 档，范围 80–2500。曲线来自 darktable `90d6c8c:data/noiseprofiles.json` 的 Leica M9 绿色通道；与亮度有关的单色噪声、空间相关性、色域限制和随机种子均沿用之前的实现。它是实测噪声曲线的模拟，不是 M9 相机软件。
- 标准 Bayer RAW 首次打开要完成原尺寸解拜尔和整图高光恢复；切预览分辨率、调滑杆和换风格不会重做。大图的恢复结果只在本地临时缓存，关闭文件后释放；临时空间不足时仍可预览，导出才重新计算。导出使用相机默认有效裁幅（无有效裁幅时使用可见区域），不放大预览。判断颗粒请看全尺寸 TIFF 的 100% 视图。

## 两套风格

两套风格是两套独立的调色模型，不是在同一个输出上套不同的饱和度。切换后，预览、观察层和全图渲染一起切换。

## 显影透视

显影透视常开。默认左边是观察层，右边是成片。「原图对比」以未加影调、风格和颗粒的输入替代左侧观察层。两边共用相同的画幅、缩放和坐标，对比初始中线居中；返回时保留此前的观察层、取样点与透视分界位置。观察层和分界线都不会写入成片。

把显影透视的分界线拖到照片最左边，就能只看成片。把手停在照片外的留白中，向右拖即可拉回。调整同一张照片时保留位置，每次打开新照片都重新居中。

照片名旁的「预览」选择长边：256、512（默认）、1024 或 1600 像素。想快速试影调选前两档，想看边缘、颜色或颗粒的细节选后两档。高档重新取原片细节，小照片不会被放大；各档共用同一次全图语义分析，切档不会重算网络蒙版，也不影响全尺寸导出。窗口仍按可用空间缩放显示。

等待成片时，整张照片轮播当前照片、当前风格的 23 张空间响应，不受透视滑块位置限制。包括 4 个调色分区、人物与边界、4 层取样特征和 13 个局部引导通道。首次分析还没有真实信号时只显示照片；暂用同一风格的上一帧时会标明。成片就绪立即恢复原来的滑块位置，收在最左侧时就只显示成片。原图对比与拖动影调时不播放动画。通道矩阵和明暗差值只供手动查看。

- **调色分区**：四个连续的权重共同参与后续调色。合看时以四个权重混色，为便于区分，加重主色；也可单看 A–D 的原始权重。颜色不等于天空、皮肤等物体类别。
- **特征回声**：在照片上点一个位置，切换第 3、6、9、12 层，看哪些区域和取样位置的特征向量相似。用余弦相似度的正值着色，不是分类、检测框或注意力概率。空间精度由模型的图块决定。
- **局部引导**：查看 13 个语义引导修正通道。金色为正，蓝色为负；这是查色位置的偏移，不是亮度变化，也不是全部引导量。
- **通道交互**：三个融合阶段各有一张真实的 16 × 16 权重矩阵。悬停格子可读百分比，每行加起来为 100%。它描述通道之间的信息混合，不与画面位置一一对应。
- **人物与边界**：显示语义解码器细化前的两个响应，而不是用外部识别器勾线。
- **明暗变化**：用金色、蓝色分别显示模型相对同一高光/阴影设置下的输入实际提亮、压暗的位置。这一页是结果对照，不是中间层。

切层、点选和拖动分界线复用当前模型信号；调整影调时先保留上一帧，停稳后才更新观察层与成片。

## 桌面实现

便携包自带两套调色模型；文件指纹见 `assets/vivid/model.json` 和 `assets/model.json`。模型从整幅预览估计空间颜色和影调；导出时复用当前风格的参数，对原图每个像素执行渲染、局部细化，经典另含额外的高光模块。全图调色按网络需要分别保留 16 像素（生动）或 28 像素（经典）上下文，只写中央有效区域。照片保持离线。

## 从源码运行或打包

本仓库公开桌面程序、原生组件源码、构建脚本和许可。运行完整显影需另行准备与两个 `model.json` 清单匹配的推理资源，目录见 [源码构建说明](SOURCE_BUILD.md)。

在目标系统安装 64 位 CPython 3.10，用独立虚拟环境安装 `python -m pip install -r requirements.txt`，然后 `python app.py`。`python app.py --self-test report.json` 检查模型、16 位原尺寸导出与 ICC。原生打包：先安装 `pyinstaller==6.16.0`，再执行 `python tools/build_native.py`。在 Mac 上执行即可生成适用于本机架构的 `.app`，可由发布者自行签名、公证。自测报告放到可写位置。

桌面端基于 PySide6 / Qt，推理使用 ONNX Runtime。BPAM、DINOv2、LibRaw 和第三方依赖保留各自许可。JTL 为独立项目，不是徕卡官方软件。替换或调试所附动态框架无需修改原照片或数据；相应许可见 `notices`。
